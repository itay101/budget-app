# AGENTS.md

This file gives coding agents project-specific context. Keep it short and update it when workflows change.

## Project Overview

- Primary app or package: `budget-app`, a YNAB-style personal budgeting app (Next.js App Router + TypeScript + Tailwind, Prisma + PostgreSQL)
- Main entry points: `src/app/` (App Router routes; server actions handle mutations, no separate API layer)
- Important directories: `src/app/budgets/` (budget/account/category/transaction UI + actions), `src/app/api/` (webhooks/external endpoints), `src/lib/` (shared helpers, e.g. `money.ts` for milliunit amounts), `prisma/schema.prisma` (data model), `docs/adr/` (architecture decisions), `e2e/` (Playwright specs)

## Architecture Notes

- Module boundaries: see `CONTEXT.md` for the domain vocabulary (User/Owner/Collaborator/BudgetMembership/Invite/AuditEntry) and `docs/adr/` for locked-in schema/behavior decisions
- Generated or vendored code: `prisma/` migrations are generated by Prisma, not hand-edited
- Sensitive areas: money is stored as integer milliunits everywhere (`src/lib/money.ts`) — never introduce float arithmetic on amounts; audit trail mutations follow the single polymorphic `AuditEntry` table (ADR 0002)

- Always ask before: editing or deleting an existing test/assertion under `e2e/*.spec.ts` (see `CLAUDE.md`); adding new e2e tests doesn't need approval

## Fallow local gate

Before any `git commit` or `git push`, run `fallow audit --format json --quiet --explain --gate-marker agent`. If the verdict is `fail`, fix the reported findings before retrying. Treat JSON runtime errors like `{ "error": true, ... }` as non-blocking.

Audit defaults to `gate=new-only`: only findings introduced by the current changeset affect the verdict. Inherited findings on touched files are reported under `attribution` and annotated with `introduced: false`, but do not block the commit. Set `[audit] gate = "all"` in `fallow.toml` to gate every finding in changed files.

For non-skill agents, treat the task map below as the local onboarding source: run the listed fallow command before destructive edits, before commits, and before pull request handoff.
